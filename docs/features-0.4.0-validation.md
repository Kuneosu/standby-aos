# 밝기·프리셋·배치 지원 — 0.4.0

검증일: 2026-10-26 / Galaxy Z Fold6 `SM-F956N` / Android 16.

## 구현

- **밝기 슬라이더:** 요소 목록에서 추가하는 반투명 유리 스타일의 슬라이더. 조작 중 불투명도 100%, 조작 종료 후 1.4초 대기하고 0.3초 동안 16%로 흐려진다. 스탠바이 창의 밝기만 2~100%로 조절하며 시스템 설정을 쓰지 않는다. 일반·야간 밝기를 각각 저장한다.
- **위치 고정:** 위치·크기 고정을 켜면 드래그, 크기 손잡이, 좌표·크기 슬라이더가 잠긴다. 색상 등 다른 속성은 바꿀 수 있다.
- **정렬 지원:** 이동 중 다른 요소나 캔버스 중앙에 가까워지면 가로·세로 보조선과 스냅을 제공한다. 편집 화면에서 끌 수 있다.
- **화면 프리셋:** 현재 편집 내용을 이름 붙여 복사본으로 저장한다. 불러오기·이름 변경·덮어쓰기·삭제를 제공하며, 대체·덮어쓰기·삭제는 확인 창을 사용한다.
- **순환 목록:** 저장된 프리셋 중 직접 등록한 것만 순서대로 표시한다. 목록 순서 변경·제외·순환 켜기/끄기를 지원한다. 비어 있거나 꺼져 있으면 현재 저장 디자인을 표시한다.
- **전환:** 새 스탠바이 진입과 실제 화면 꺼짐 후 켜짐에 다음 프리셋을 선택한다. 회전·접힘에 따른 Activity 재생성은 선택을 유지한다. 좌우 스와이프는 다음 프리셋으로 이동하며 밝기 슬라이더의 입력은 제외한다.
- **파일 보존:** 기본 디자인·임시 편집·모든 저장 프리셋에서 쓰는 사진·GIF의 합집합을 보관한다. 순환에서 제외한 프리셋의 파일도 유지한다.

기존 0.3.1의 편집 변경 누적 방식을 유지했다. 저장 형식은 기존 `scene_v1`에 선택 필드를 추가하고 별도의 프리셋 키를 추가하는 방식이며, 기존 요소의 위치 고정 기본값은 꺼짐이다.

추가 단위 검사 8개는 순환 포함·제외·순서·빈 목록·단일 프리셋·중앙 정렬·고정 요소·밝기 범위·최초 화면 켜짐과 재점등의 구분을 다룬다. 기존 단위 검사 29개도 통과했다.

추가 기기 검사 7개는 다음을 확인했다.

1. 실제 밝기 슬라이더 드래그가 창 밝기와 저장값을 바꾸고, 같은 제스처가 프리셋을 넘기지 않음. 활성·비활성 투명도와 배경 스와이프 전환도 확인.
2. 고정한 요소의 드래그·크기 변경 차단, 고정 해제 후 이동.
3. 실제 드래그 중 다른 요소의 중앙으로 스냅하고 보조선 표시·종료.
4. 실제 EditorActivity·ViewModel·DataStore로 프리셋 저장, 순환 선택·순서 변경·제외, 삭제·불러오기·재진입.
5. 진입 ID가 같으면 선택 유지, 명시적 스와이프와 새 진입에서만 진행. 디스크 재오픈 후 마지막 선택·밝기 보존.
6. 순환에서 제외한 프리셋의 이미지가 기본 디자인 저장·임시 편집 취소 때 보존되고 마지막 참조 제거 후 정리됨.
7. 밝기 요소와 위치 고정의 저장·복원 및 이전 버전 디자인 호환.

첫 기기 검사에서는 정렬 시나리오 1개가 실패했다. 고정된 손가락 종점과 실제 요소 중심 사이에 기기 터치 슬롭 차이가 있어 스냅 범위 밖에 멈춘 경우였다. 검사를 실제 요소 중심을 읽고 가이드에 접근하는 동작으로 바꿔, 마지막 실행에서 보조선과 정확한 중앙 정렬을 확인했다. 제품의 스냅 임계값은 늘리지 않았다.

## 실제 잠금 화면 및 설치

자동 계측과 실제 잠금 화면 검사는 사용 앱과 분리한 `dev.kwonsu.standby.validation`에서 실행했다. 사용 앱의 설정·미디어는 검사 전에 별도로 백업했다.

- **잠금·충전·가로 상태:** 사용자가 실제 밝기 슬라이더 조작과 배경 스와이프에 따른 심해·노을 전환을 확인했다. 순환에 넣지 않은 세 번째 검사 프리셋은 선택 대상에서 제외했다.
- **화면 재점등:** 검사 시계가 표시된 상태에서 실제 화면을 끄고 켰다. 꺼짐 상태 `mWakefulness=Dozing`을 확인했고, 다시 켜졌을 때 노을에서 심해로 한 번 전환했다. 회전에 따른 Activity 재생성 로그가 함께 발생했지만, 같은 진입 ID는 같은 프리셋을 유지했다.
- **검사 판정 보정:** 최초 수집 스크립트는 `preset_entry` 로그가 정확히 한 줄이어야 한다고 가정해 실패했다. 원본 기록의 진입 ID와 선택 프리셋을 대조하면 이전 진입의 재생성 한 건과 새 진입의 중복 기록 두 건이며, 실제 선택 전환은 한 번이다. 동일 진입 ID를 중복 제거한 판정 결과를 저장했다. 제품 코드는 이 판정 보정 과정에서 변경하지 않았다.
- **사용 앱 업데이트:** `dev.kwonsu.standby`를 삭제하지 않고 `0.3.1`에서 `0.4.0`(versionCode 5)으로 업데이트했다. 설정 파일과 GIF 파일의 SHA-256이 검사 전·설치 직전·설치 직후 동일했다.
- **복구·정리:** 검사 앱과 계측 앱을 제거했고, 사용 앱의 자동 감시를 다시 켰다. `ChargeMonitorService`의 `isForeground=true`로 실행 상태를 확인했다.
