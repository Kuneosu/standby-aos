# 앱별 알림 누적과 개별 제거 — 0.8.0

2026-10-26 / versionCode 11.

## 동작

이전 버전은 Android의 활성 알림 목록을 다시 읽어 표시했으므로 같은 알림 ID가 갱신되면 앞선 내용이 대체됐다. 0.8.0은 게시 이벤트를 순서대로 처리해 수신 기록을 별도로 쌓는다.

- 앱별 최신 알림·개수를 먼저 표시하고 최신 알림 시각이 가장 최근인 앱을 위에 배치한다.
- 앱 묶음을 누르면 누적 알림을 최신순으로 펼친다. 앱별로 접고 펼칠 수 있다.
- 펼친 개별 항목을 오른쪽→왼쪽으로 충분히 밀면 스탠바이 기록에서 제거한다. 짧게 밀면 돌아온다.
- 세로 드래그는 목록 스크롤, 오른쪽 드래그는 기존 패널 닫기다. 프리셋 전환과 구분한다.
- 시스템 알림 삭제·읽음 처리·답장은 실행하지 않는다. 시스템에서 알림이 제거돼도 수신 기록은 남는다.
- 최근 500개를 보관한다. 기능 시작 전 이미 사라진 알림은 복원하지 못한다. 최초 연결 때 현재 전달되는 알림의 메시지는 가져온다.

## 누적·중복·공개 범위

`onNotificationPosted`마다 전달된 알림 객체를 처리한다. 새 이벤트가 오면 앞선 읽기 요청을 취소하던 처리를 없애고 순서가 있는 이벤트 큐를 사용한다. MessagingStyle은 발신자·메시지 시각·내용으로 안정적인 식별자를 만들고 각 메시지를 나눈다. InboxStyle 줄 목록도 나누며, 일반 알림은 같은 출처에서 제목·본문이 그대로 갱신되면 중복을 제외한다.

같은 묶음을 다시 받거나 재연결해도 중복되지 않는다. 개별 제거는 기록을 지우면서 수신 식별자를 유지해 같은 항목이 되살아나지 않게 한다. 중복 방지 식별자는 최근 5,000개, 일반 알림 출처의 마지막 비교값은 최대 1,000개로 제한한다. 식별자·비교값은 SHA-256이다. 하위 기록이 있는 합성 그룹 요약은 제거해 중복을 줄인다.

현재의 선택 앱·공개 규칙은 보관 목록에도 적용한다. 수신 당시 선택하지 않은 앱은 보관하지 않으며, 내용 숨김 상태에서는 원문을 보관하지 않는다. 뒤에 내용 표시로 바꿔도 수신 때 저장하지 않은 과거 원문은 복원하지 않는다. 현재 활성 알림으로 다시 전달되는 같은 수신은 규칙에 맞춰 갱신하며 새 행으로 중복 추가하지 않는다.

기록은 앱 전용 `notification_history.enc`에 AES-256-GCM으로 저장한다. 암호화 키는 Android Keystore에서 생성하고, 쓰기는 AtomicFile로 처리한다. 평문 파일을 만들지 않으며 로그에 제목·본문·알림 키를 기록하지 않는다. 파일을 읽지 못하면 원본 파일을 유지하고 경고를 표시하며, 쓰기 실패도 UI로 알린다.

공식 근거: [알림 게시 콜백](https://developer.android.com/reference/android/service/notification/NotificationListenerService#onNotificationPosted(android.service.notification.StatusBarNotification)), [Android Keystore](https://developer.android.com/privacy-and-security/keystore).

## 검증 상태

Debug·Validation·계측 APK 빌드와 단위 검사를 실행했다. 단위 검사 74개가 통과했다. 추가 단위 검사는 같은 알림 ID의 내용 누적, 일반 갱신 중복 방지, 시스템 제거 후 보관, 묶음 재전달, 개별 제거 후 재유입 방지, 보관 개수 제한, 현재 규칙 재적용, 앱별 정렬, 합성 요약 제거, 공개 범위 변경을 다룬다.

Galaxy Z Fold6의 별도 검사 패키지에서 알림 관련 계측 검사 15개가 모두 통과했다(12.37초). 실제 Android 메시지 묶음·InboxStyle 추출, 암호화 저장·재오픈·제거 상태 보존·파일 변조 감지, 앱별 펼치기·최신순 정렬·짧은 드래그 취소·왼쪽 개별 제거·오른쪽 패널 닫기·세로 스크롤을 확인했다. 기존 알림 공개 규칙·선택 앱 필터·저장·유리 블러 검사도 포함했다. 검사 입력은 예시 알림이며 개인 알림 내용이나 화면은 수집하지 않았다.

| 구분 | 결과 |
| --- | --- |
| Debug·Validation·계측 APK 빌드 | 통과 |
| 단위 검사 | 74개 통과 |
| Debug·Validation Lint | 각각 오류 0개, 기존 경고 14개 |
| Fold6 알림 관련 계측 검사 | 15개 통과 |
| 사용 앱 업데이트 | 0.8.0 / versionCode 11 설치 확인 |
| 기존 설정·사진·GIF 보존 | 6개 파일의 검사 전·업데이트 전·업데이트 후 SHA-256 일치 |
| 자동 감시·알림 수신 연결 | 기존 켜짐 상태 복구 확인 |
| 검사 앱·계측 앱 | 제거 완료 |

기존 선택 앱·공개 규칙을 유지했다. 사용 앱에 암호화 기록 파일이 생성되는 것까지 확인했으며, 개인 알림 내용을 열어 검증하지 않았다. 실제 기기의 누적·펼치기·개별 제거는 사용자가 정상 동작한다고 확인했다. 파일 재오픈 검사는 실제 암호화 파일을 사용했으며, 카카오톡 앱이 전달하는 실제 알림 구성과는 구분한다.
