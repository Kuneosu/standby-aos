# 연속 편집 되돌림 수정 — 0.3.1

검증일: 2026-10-26 / Galaxy Z Fold6 `SM-F956N` / 기존 앱 0.3.0 → 0.3.1.

## 결과

다른 버튼을 수정하면 앞선 위치 변경이 원복되고, 삭제한 버튼이 다시 나타나는 오류를 수정했다. 최신 편집 상태에 해당 변경을 누적하도록 바꿨다. 현재 설정·임시 편집·미디어를 보존한 채 실기기에 0.3.1을 설치했고 자동 감시를 다시 켰다.

## 원인과 변경

`SceneEditor`의 로컬 `changeElement` 함수가 당시의 `scene`을 캡처한 채 `::changeElement`로 전달됐다. 이 콜백이 재사용되면 이전 요소 목록을 기반으로 전체 장면을 다시 만들기 때문에, 다른 요소의 이동이나 삭제를 덮어쓸 수 있었다.

- `EditorViewModel.change`는 완성된 과거 장면 대신 변경 함수를 받아 현재 `scene`에 적용한다.
- `SceneEditor`는 요소 이동·삭제·추가·순서, 배경·폰트·색상 변경을 최신 장면 기준으로 처리한다.
- 장면을 캡처하는 로컬 함수 참조를 제거했다. 요소 수정은 현재 목록에서 해당 ID만 교체하므로 이미 삭제된 다른 요소가 다시 추가되지 않는다.
- 데이터 저장 형식은 유지했다. 데이터 초기화나 마이그레이션은 하지 않았다.

## 수정 전후 실기기 검사

검사는 사용 앱과 분리된 `dev.kwonsu.standby.validation`에서 실행했다.

| 시나리오 | 0.3.0 재현 | 0.3.1 결과 |
| --- | --- | --- |
| 야간 버튼 이동 → 닫기 버튼 이동 → 너비 조정 → 다시 야간 버튼 조정 | 두 번째 버튼 이동 시 야간 버튼이 원래 좌표로 복귀 | 앞선 이동과 너비 변경 모두 유지 |
| 닫기·야간 버튼 연속 삭제 → 남은 배터리 이동·너비 조정 → 저장 | 남은 요소를 수정한 뒤 요소가 4개에서 6개로 복귀 | 4개 유지, 삭제한 버튼은 화면에서도 없음 |
| 실제 편집 Activity에서 이동·삭제·수정 → 임시 저장 재진입 → 저장 → 재진입 | 이번 수정 후 통합 검사로 추가 | 모든 변경 유지, 기존 폰트·배경 유지 |

단순 연속 삭제만으로는 첫 두 삭제가 유지됐으며, 이후 남은 요소를 수정하는 단계에서 삭제가 되돌아가는 것을 직접 재현했다.

수정 전 재현 검사 **2개 실패** → 같은 검사 **2개 통과** → 최종 전체 기기 검사 **15개 통과**. 기존 기기 검사 12개에 이번 회귀 검사 3개를 추가했다.

- 수정 전 원본 (`output/editor-state-fix/before.txt`, 로컬 전용)
- 동일 시나리오 수정 후 원본 (`output/editor-state-fix/after-targeted.txt`, 로컬 전용)
- 최종 전체 기기 검사 (`output/editor-state-fix/after-full.txt`, 로컬 전용)
- 빌드·단위 검사·Lint 실행 로그 (`output/editor-state-fix/build-validation.txt`, 로컬 전용)
