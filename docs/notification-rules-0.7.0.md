# 스탠바이 전용 앱별 알림 규칙 — 0.7.0

2026-10-26 / versionCode 9.

## 변경 이유와 사용법

0.6.0은 모든 앱에 잠금 화면 공개 범위를 적용했다. 카카오톡이 비공개로 표시한 알림은 원문이 Android API에 전달되어 있어도 스탠바이 앱에서 추출하지 않고 “잠금 해제 후 내용을 확인하세요.”라는 안내로 대체했다.

0.7.0에서는 **앱 → 알림 패널 → 앱별 알림 규칙**에서 스탠바이 전용 규칙을 고른다. 앱을 검색하거나 목록에서 선택하면 네 가지 규칙이 나온다. 선택하면 즉시 저장되고 이미 도착한 알림도 다시 계산한다.

| 규칙 | 동작 |
| --- | --- |
| 숨김 | 해당 앱 알림 제외 |
| 잠금 설정 따름 | 기존 공개 범위·공개 버전 처리 유지 |
| 내용 표시 | Android가 알림 리스너에 전달한 제목·본문 표시. 잠금 화면 공개 범위 메타데이터로 추가 가리지 않음 |
| 내용 숨김 | 제목·본문 대신 앱 이름·시간과 일반 안내 표시 |

사용자 요청에 따른 초기값은 `com.android.systemui` 숨김, `com.kakao.talk` 내용 표시다. 실제 기기에서 두 패키지의 설치를 확인했다. 다른 앱은 잠금 설정을 따른다. 사용자가 저장한 선택은 초기 예외보다 우선한다.

휴대폰 잠금 설정·카카오톡 설정·시스템 알림 채널을 수정하지 않는다. 알림 읽기 권한은 이미 허용한 것을 사용한다. Android가 가려서 전달한 내용이나 원래 앱이 전달하지 않은 내용은 복원하지 않는다. Android 15 이상은 일부 민감한 알림 내용을 알림 리스너에 전달할 때 가릴 수 있다. [공식 동작 설명](https://developer.android.com/about/versions/15/behavior-changes-all#otp-redaction).

## 구현과 보존

- 설정은 기존 DataStore의 별도 `notification_rules_v1` 키에 저장한다. 화면·임시 편집·프리셋·공통 배치·미디어 형식은 변경하지 않는다.
- 저장된 규칙이 없으면 요청한 초기값을 사용한다. 손상된 JSON 또는 알 수 없는 규칙은 내용을 공개하는 예외로 되돌리지 않고 잠금 설정을 따른다.
- 리스너는 저장된 규칙을 읽은 뒤 알림을 추출한다. 규칙 변경 시 기존 표시 내용을 즉시 비우고 활성 알림을 다시 읽는다. 이전 요청은 취소하고 최신 결과만 게시한다.
- 숨김·내용 숨김은 원문을 표시 모델에 추출하지 않는다. 내용 표시는 전달받은 원문을 메모리에서만 처리하며, 원래 Android 알림 객체나 시스템 상태는 바꾸지 않는다.
- 메시지 본문은 긴 본문·일반 본문·줄 목록 순으로 읽고 비어 있으면 MessagingStyle의 최근 메시지에서 가져온다. 시스템이 제공한 가림 문구는 다른 내용으로 대체하지 않는다. [AndroidX MessagingStyle](https://developer.android.com/reference/androidx/core/app/NotificationCompat.MessagingStyle#extractMessagingStyleFromNotification(android.app.Notification)).
- 알림 내용·제목·키는 파일이나 진단 로그로 저장하지 않는다. 설정 화면은 실행 가능한 앱, 현재 알림 앱, 저장된 규칙 앱을 합친다. 전체 패키지 조회 권한은 추가하지 않는다.

## 검증

| 항목 | 결과 |
| --- | --- |
| Debug·Validation·계측 APK 빌드 | 성공 |
| 단위 검사 | 60개 통과, 실패·오류·생략 0 |
| Debug·Validation Lint | 각각 오류 0개, 기존 경고 14개 |
| 실제 기기 검사 | 고유 시나리오 36개 최종 통과: 최초 35개 + 설정 흐름 재실행 1개 |
| 사용 앱 업데이트 | 0.7.0 설치, 설정·미디어 6개 파일 보존, 감시·알림 연결 복구 |
| 사용 앱에서 초기 규칙 표시 | 시스템 UI 숨김·카카오톡 내용 표시 확인 |
| 실제 카카오톡 내용 표시·시스템 UI 제외 | 사용자가 정상 동작 확인 |

추가 단위 검사는 초기 예외·사용자 선택 우선·앱 숨김·원문 공개·내용 숨김·잠금 설정 복귀를 다룬다. 기기 검사는 저장 후 디스크 재오픈과 디자인 보존, 잘못된 규칙의 안전한 처리, 실제 설정 화면의 검색·선택·화면 재생성·재진입, Android 알림 원문과 공개 버전의 선택·MessagingStyle 본문 추출을 다룬다.

첫 전체 실행에서 35개가 통과했고, 새 설정 흐름 검사는 마지막 이미지 저장 함수의 Boolean 반환이 테스트 메서드까지 추론되어 JUnit의 void 요구 조건을 만족하지 못했다. 검사 코드에 `runBlocking<Unit>`를 명시한 뒤 해당 시나리오를 재실행해 통과했다. 이 수정으로 제품 코드는 바꾸지 않았다. 최종 수치는 최초 35개와 대상 재실행 1개를 합친 것이며 전체 36개를 다시 실행했다고 간주하지 않는다.

실제 설정 화면에서 카카오톡을 숨기고 시스템 UI의 내용을 가린 다음, 화면 재생성·검색·재진입 후 선택이 유지되는지 확인했다. 이후 카카오톡 내용 표시·시스템 UI 숨김으로 되돌리는 과정까지 통과했다. 자동 검사에는 개인 알림을 사용하지 않았다. 사용자가 실제 스탠바이에서 시스템 UI가 숨겨지고 카카오톡 내용이 보인다고 확인했다. 자동 검사와 사용자 확인을 구분해 기록한다.

## 설치와 기존 상태 복구

사용 앱을 제거하거나 데이터를 초기화하지 않고 0.6.0에서 0.7.0으로 업데이트했다. 설정·미디어 6개 파일의 SHA-256이 검사 전·설치 직전·직후 모두 같았다. 새 규칙은 저장값이 없는 경우의 초기값으로 적용하므로 업데이트 과정에서 기존 설정 파일을 다시 쓰지 않았다.

검사 패키지 두 개를 제거하고 자동 스탠바이 감시를 다시 켰다. `ChargeMonitorService`의 `isForeground=true`와 시스템의 알림 리스너 연결을 확인했다. 기존 알림 접근 권한을 그대로 사용했다. 설치된 앱의 실제 설정 화면에서도 시스템 UI 숨김·카카오톡 내용 표시를 확인했다.

장시간 전력·발열, 다른 기기의 알림 정책은 이번 범위에 포함하지 않는다.
