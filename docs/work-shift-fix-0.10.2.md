# 출퇴근 버튼·폭죽 표시 수정 — 0.10.2

2026-10-28 / versionCode 21.

출근·퇴근 버튼에 짙은 바탕을 적용하고, 폭죽 애니메이션을 끝까지 표시한 뒤 재생 완료를 저장한다. 퇴근 후 12시간은 출퇴근 게이지에만 적용하며 스탠바이의 시계·날짜·배터리·배경은 유지한다.

## 확인한 원인과 수정

### 퇴근 후 12시간

- 기존 코드의 `COOLDOWN`은 `WorkShiftGauge`만 숨긴다. 스탠바이 진입·종료는 잠금·충전·가로 조건으로 별도 판단하며 근무 상태를 참조하지 않는다.
- 별도 검사 앱에서 실제 퇴근 버튼을 누른 직후와 화면 재진입, 12시간 직전에도 시계·날짜·배터리·배경이 남고 게이지만 숨는 것을 확인했다. 12시간 경계에서는 출근 버튼이 다시 나타난다.
- 편집 안내를 “출퇴근 게이지만 숨기며, 시계와 배경은 계속 표시”로 명확히 했다.
- 화면 전체가 숨는 별도 현상은 이번 검사에서 재현되지 않았다. 실제 사용 앱의 퇴근 기록을 변경하거나 12시간을 실제로 기다리지는 않았다.

### 100%인데 퇴근 버튼이 보이지 않음

- 실사용 0.10.1의 저장 상태는 근무 완료·퇴근 미처리였다. 잠금·충전·가로 상태로 자동 진입한 실제 화면에서 100%와 퇴근 버튼의 UI 노드를 확인했다.
- 선택한 게이지 색상과 밝은 배경색이 같았고, 버튼의 글자·옅은 테두리·투명한 바탕이 배경과 섞였다. 기능상 존재해도 눈으로 구분할 수 없는 상태였다.
- 버튼에 불투명한 짙은 바탕과 선명한 테두리를 적용했다. 선택 색상은 유지하며, 너무 어두운 색상은 버튼 글자만 밝게 보정한다. 출근 버튼에도 같은 규칙을 사용한다.
- 같은 색 배경에서 실제 렌더링 픽셀의 대비와 손가락 입력을 검사했고, 가로·세로의 완료 버튼을 확인했다.

### 100% 폭죽

- 기존에도 약 4.2초의 전체 화면 폭죽이 있었다. 다만 애니메이션 시작 전에 재생 완료를 저장해, 화면 회전·재생성·프리셋 전환 도중 사라져도 다시 재생하지 못했다.
- 활성 화면이 포커스를 얻은 뒤 시작하고, 애니메이션의 종료 콜백에서 완료를 저장하도록 수정했다. 중간에 중단되면 다음 표시 때 다시 재생한다.
- 오래된 애니메이션의 콜백이 새로운 근무의 완료 기록을 소비하지 않도록 근무 시작 식별값을 대조한다.
- 밝은 배경에서도 보이도록 폭죽 입자에 어두운 외곽을 추가했다. 실제 두 프레임의 픽셀 변화와 전체 화면 범위를 확인했다.
- 이전 버전에서 이미 재생 완료로 저장한 근무 기록은 그대로 유지한다. 해당 과거 근무의 폭죽을 강제로 다시 재생하지 않는다.

첫 수정 후 실행은 14개 통과·1개 실패였다. Activity 재개 검사에서 테스트의 정지된 Compose 시계가 비동기 창 포커스를 반영할 프레임을 진행하지 않아 대기 시간이 초과됐다. 검사 대기 중 프레임을 진행하도록 보완한 뒤 새 회귀 검사 5개가 모두 통과했다. 실패 로그도 보관한다.

검사 범위는 같은 색 배경의 버튼 대비·실제 터치, 폭죽 도중 화면 재구성·재생 완료 후 재진입, Activity 일시정지·재개, 실제 기기 시계에 따른 마감 전환, 가로·세로, 12시간 숨김 경계, 근무 기록의 디스크 재개방, 공통 요소 자동 추가와 개별 색상 저장을 포함한다.

12시간 경계와 대부분의 완료 시각은 검사 앱의 시간을 지정해서 검증했다. 별도 시나리오에서는 기기 시계를 바꾸지 않고 검사 근무의 마감을 수 초 뒤로 설정해 실제 시간 갱신으로 100% 전환을 확인했다. 하루 연속 사용이나 12시간 실시간 대기는 수행하지 않았다. 0.10.2 사용 앱 설치 후 자동 감시 복구와 알림 서비스 연결을 확인했으며, 잠금·충전·자세별 자동 진입·종료는 재검사하지 않았다.

## 데이터와 설치 상태

- 사용자 승인 후 사용 앱을 **0.10.2 / versionCode 21**로 업데이트했다. 앱의 **자동 스탠바이 켜기**로 자동 감시를 복구하고 foreground 실행·알림 서비스 연결을 확인했다.
- 검사 앱 2개를 제거했고, 실사용 자동 감시의 foreground 실행과 알림 서비스 연결을 확인했다.
- 추적 파일 7개 중 근무 기록·미디어 6개는 검사 전후 해시가 같다. 설정 파일은 실제 스탠바이 자동 진입으로 순환 기록이 갱신돼 해시가 달라졌으므로, 전체 설정 파일이 바이트 단위로 같다고 판정하지 않았다.
- 이후 설치 단계에서는 별도로 다시 기준 해시를 기록했다. **설치 직전·설치 직후·자동 감시 복구 후 설정·근무 기록·미디어 7개 파일의 해시가 모두 같다.**
- 사용 앱의 근무 기록과 원본 미디어는 편집하지 않았다. 실제 표시 문제를 확인하기 위한 화면 캡처와 배치·상태 요약만 보관했다.
