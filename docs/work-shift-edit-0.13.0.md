# 출근 시각 변경 — 0.13.0

2026-10-29 / versionCode 26.

출근 시각을 잘못 입력한 경우, 실제 스탠바이에 표시된 출퇴근 게이지를 길게 눌러 고칠 수 있다. 현재 저장된 출근 시각을 다이얼에 불러오며 **HH:mm로 변경**을 누르면 퇴근 예정 시각과 진행률을 다시 계산한다.

## 동작

- 가로·세로 게이지에서 길게 누르면 진동과 함께 수정 화면을 연다. 짧게 누르는 동작은 시간을 바꾸지 않는다.
- **취소**하면 저장하지 않는다. 같은 시각으로 확정하면 기존 완료·폭죽 기록을 유지하고 수정 화면을 닫는다.
- 출근 날짜는 그대로 유지한다. 전날 22시에 출근한 기록을 자정 이후 수정해도 전날 날짜를 기준으로 계산한다.
- 퇴근 예정 시각은 기존 규칙인 **출근 당일 17시와 출근 후 9시간 중 더 늦은 시각**이다. 미래 시각을 고르면 해당 시각까지 0%로 대기한다.
- 수정 화면을 열어 둔 동안 기존 퇴근 예정 시각이 지나도 새 시각을 확정할 수 있다. 수정 화면 위에는 폭죽을 재생하지 않는다. 새 퇴근 예정 시각이 아직 지나지 않았다면 근무 중으로 돌아간다.
- 수정한 퇴근 예정 시각이 이미 지났다면 기존 자동 퇴근·폭죽·12시간 숨김 규칙을 적용한다.
- 다른 근무로 바뀐 뒤 도착한 오래된 수정 요청과 이전 폭죽 완료 콜백은 현재 기록을 덮어쓰지 않는다.
- 꾸미기 미리보기에는 실제 근무 수정 동작을 연결하지 않는다. 자동 퇴근 후 숨겨진 게이지의 표시 정책은 유지한다.

## 검증

| 구분 | 결과 |
| --- | --- |
| Debug·Validation·계측 APK 빌드 | 통과 |
| 단위 검사 | 101개 통과 |
| Fold6 별도 검사 앱 | 출퇴근 관련 19개 통과 |
| Debug·Validation Lint | 각 오류 0개, 기존 경고 14개 |

실기기에서는 실제 길게 누르기, 짧게 누르기, 취소, 08:00 → 09:00 변경, 진행률 22% → 11%·예정 퇴근 17:00 → 18:00 반영, 재진입 시 새 시각 불러오기, 같은 시각 확정, 회전된 화면의 세로 게이지, 자정 이후 원래 날짜 유지, 수정 중 기존 마감 경과를 확인했다. 디스크를 다시 열어 저장된 수정값과 이전 콜백 차단도 검사했다. 기존 자동 퇴근·폭죽 재생 완료·중단 후 재개·12시간 대기 회귀 검사를 포함한다.

검사는 실사용과 분리된 `dev.kwonsu.standby.validation`에서 수행했다. 근무 경계 검사는 검사 앱에 지정한 시간을 사용했으며 기기 시계를 바꾸지 않았다. 기존 회귀 중 수 초 뒤 실제 시간 경과로 자동 퇴근하는 검사도 통과했다. 잠금·충전·자세별 전체 자동 진입, 실제 12시간 대기, 장시간 사용은 이번에 다시 검사하지 않았다.

실사용 설정·근무 기록·미디어 7개 파일은 검사 전후 해시가 동일했다. 검사 패키지 2개를 제거했으며 실사용 앱의 자동 감시 foreground 실행과 알림 서비스 연결을 확인했다.

이후 사용자 승인에 따라 검증한 APK와 SHA-256이 일치하는 **0.13.0 / versionCode 26을 Fold6에 업데이트 설치**했다. 설치 직후와 자동 감시 복원 후 모두 기존 7개 파일의 해시가 일치했다. 기기 패키지 정보와 앱 화면에서 버전을 확인했으며, 설치 전 켜져 있던 자동 감시를 다시 켜 foreground 실행과 알림 서비스 연결을 확인했다. 실사용 근무 시각은 변경하지 않았고, 설치 후 자동 진입 조건 검사는 별도로 반복하지 않았다.
